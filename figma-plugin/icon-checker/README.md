# 아이콘 검사기 — Figma 플러그인

`docs/ICON_STYLE_GUIDE.md` (Spec v2) 의 QA 체크리스트를 Figma 안에서 자동으로 돌린다.
현재 범위는 **Multicolor 전용 규칙 + 3스타일 공통 규칙**이고, 리포트만 낸다 — 아이콘을 고치지 않는다.

## 설치

빌드 과정이 없다. Figma 데스크톱 앱에서 한 번만 등록하면 된다.

1. Figma 데스크톱 앱 → 메뉴 `Plugins` › `Development` › `Import plugin from manifest…`
2. 이 폴더의 `manifest.json` 을 고른다
3. 이후로는 `Plugins` › `Development` › **아이콘 검사기** 로 실행한다

## 쓰는 법

| 버튼 | 대상 |
|---|---|
| **선택 검사** | 고른 아이콘. 프레임·섹션·컴포넌트 세트를 고르면 그 안의 24 × 24 아이콘을 모두 훑는다 |
| **페이지 전체** | 현재 페이지의 모든 24 × 24 아이콘 |

- 상단 알약(위반 · 경고 · 정보)을 눌러 표시를 켜고 끈다. **정보**는 기본으로 꺼져 있다
- **항목을 누르면 그 레이어가 캔버스에서 선택되고 화면에 맞춰진다.** 마지막으로 누른 항목은 표시가 남는다
  - 항목 오른쪽 칩이 어느 레이어로 가는지 미리 알려 준다 (설명에 이미 이름이 있으면 생략)
  - 아이콘 이름 줄을 누르면 아이콘 프레임으로 가면서 접고 펴진다
  - 레이어가 다른 페이지에 있으면 그 페이지로 옮겨 가고, 지워졌으면 그렇다고 알린다
- **리포트 복사**는 마크다운으로 클립보드에 넣는다

hidden 레이어는 P24-08 의 원본 백업으로 보고 검사에서 제외한다. 다만 **아이콘 바로 아래**에 둔 것만 백업으로 세고, 보이는 레이어 안쪽에 숨은 노드는 따로 알린다 — 실수로 감춘 요소일 수 있다.

## 검사 항목

### 공통 — Line · Fill · Multicolor

| 코드 | 항목 | 판정 |
|---|---|---|
| `C01` | 캔버스 24 × 24 · Component 여부 | 위반 / 경고 |
| `C02` | 라이브 영역과 패딩 (20×20=2 · 18×18=3 · 자유=1) · 배지 확장 한계 1.8 | 위반 / 경고 |
| `C03` | 컨테이너 radius — 변 18 → 3.5, 변 16 → 3.0 | 위반 |
| `C07` | Boolean 연산 잔존 · 중첩 깊이 | 경고 |
| `C08` | 원본 백업 — 아이콘 바로 아래 hidden 레이어 · 되돌릴 수 있는 형태인지 · 안쪽에 숨은 노드 | 경고 |
| `C09` | 네이밍 `ic_{object}_{modifier}_{style}` · 대문자·한글·하이픈 금지 | 위반 |
| `E1` `E2` `E3` | effect · blend mode · mask | 위반 / 경고 |

### Multicolor 전용

| 코드 | 항목 | 판정 |
|---|---|---|
| `M1` | stroke 0건 | 위반 |
| `M2` | opacity · fill-opacity 미사용 | 위반 |
| `M3` | Subtract 미사용 | 위반 |
| `M4` | 덮이지 않은 evenodd 구멍 — 색 배경에서 배경이 비치는 자리 | 경고 |
| `M5` | 레이어 쌓인 순서 (아래 → 위) — 개수는 판정하지 않는다 | 정보 |
| `M6` | 주 hue 1개 + white. 두 번째 hue 는 우하단 배지에만. Gray 는 중립이라 예산 제외 | 위반 / 경고 |
| `M7` | 모든 색이 토큰 값과 정확히 일치 — 어긋나면 가장 가까운 토큰을 제시한다 | 위반 |
| `M8` | 코너 라운드 계단 · `r ≥ 0.5` · 한 아이콘 3종 이하 | 위반 / 경고 |
| `M9` | 최소 치수 — 두께 ≥ 1.5, 독립 도형 ≥ 2.0 | 위반 / 경고 |

### Line 전용

`L1` 두께 (기본 1.5 · `_thin` 1 · `_thick` 2, 한 아이콘 안 혼용 금지) · `L2` 획 정렬 Center · `L3` round cap / join · `L4` outline stroke 여부.

### M4 — 구멍을 어떻게 가려내는가

evenodd 로 뚫은 자리에는 아무것도 칠해지지 않아 뒤가 비친다. 흰 배경에서는 구멍도 희게 보여 눈에 띄지 않다가,
색 위에 얹는 순간 드러난다. 그래서 가이드는 뚫지 말고 **그 자리에 다른 색 면을 얹으라**고 한다 (P21 · P24-M4).

다만 `evenodd` 라는 사실만으로는 판정할 수 없어 두 단계를 더 본다.

| 단계 | 세트 205종에서 걸리는 수 |
|---|---|
| evenodd + 루프 2개 이상 | 102종 |
| + 한 루프가 다른 루프 **안에** 있는지 (떨어진 두 조각은 구멍이 아니다) | 27종 |
| + 그 자리를 **덮는 면이 없는지** (덮여 있으면 가이드대로 된 상태다) | 5종 |

덮임은 bbox 근사로 본다 — 구멍의 중심이 다른 면 안에 있고 6할 이상 겹치면 덮은 것으로 친다.

마지막 한 겹은 자동으로 가려지지 않는다. **덮어야 할 구멍**과 **의도적으로 열린 실루엣**(의자 살 사이, 포크 갈래)은
둘 다 닫힌 내부 루프라 기하로 구분되지 않는다. 그래서 위반이 아니라 경고다.

### 검사하지 않는 것

Key shape 의 시각 무게, 눈으로 맞추는 정렬, 축소 가독성(P24-06), 저장소 등록(M10)은 사람이 본다.
**좌표**(P24-04 · P21)는 아예 검사하지 않는다 — Export 를 캔버스 크기 전체로 하므로 0.5 스냅도 소수점 자리수도 결과에 영향이 없다.
**레이어 개수**(P24-M5)도 판정하지 않는다 — P13 의 Base → Accent → Detail → Badge 는 역할 순서이지 노드 개수가 아니다. 역할 하나가 여러 조각으로 나뉘거나(브라우저의 상단 바 + 사이드바) 2 개로 끝나는 것(원형 컨테이너 + white 글리프) 모두 정상이다.

## 회귀 테스트

Figma 노드를 흉내 낸 객체로 규칙을 직접 돌린다. 규칙을 고친 뒤 갈래가 살아 있는지 확인한다.

```
node figma-plugin/icon-checker/test.js
```

## 팔레트 동기화

색 검사는 `docs/color-tokens.json` 을 출처로 쓴다 (9 hue × 11 step · 99색).
토큰이 바뀌면 아래를 한 번 돌려 `code.js` 의 `PALETTE` 블록을 다시 쓴다.

```
node figma-plugin/icon-checker/sync-palette.js
```

## 가이드와 다른 점

현재 세트 205종을 다시 계측한 결과, 아래 두 가지는 가이드 본문과 어긋나 실측을 따랐다.

| 항목 | 가이드 | 실측 (205종) | 플러그인 |
|---|---|---|---|
| 컬러 팔레트 | P14 의 7 family × 5 step (35색) | 세트가 쓰는 고유 hex 71개 중 P14 와 일치하는 것은 **3개**뿐. `docs/color-tokens.json` 과는 fill 기준 **98.3%** 일치 | `color-tokens.json` 을 출처로 씀 |
| 코너 라운드 계단 | P08 의 7단 (57종 기준) | 코너 1387개 중 `r 2.0` 이 94개(6.8%)로 1.5·3.0 보다 많다 | `R-200 = 2.0` 을 8번째 단으로 추가 |

두 항목 모두 가이드 쪽 갱신이 필요하다.
